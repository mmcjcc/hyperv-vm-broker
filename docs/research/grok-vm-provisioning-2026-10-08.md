## 1. Ubuntu 24.04 LTS cloud images on Hyper-V Gen2

**Use the generic QCOW2 image, not the Azure VHD.** Canonical’s artifact reference says the published `.img` is a QCOW2 disk (example name `noble-server-cloudimg-amd64.img`) and that the Azure VHD “will not function outside of Azure, including on-premises Hyper-V.” ([artifacts](https://documentation.ubuntu.com/public-images/public-images-reference/artifacts/))

Pin the release stream, not daily:

- Generic: `https://cloud-images.ubuntu.com/releases/24.04/release/ubuntu-24.04-server-cloudimg-amd64.img`
- Daily equivalent (do not pin): `https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img` — the directory listing calls this file a “QCow2 UEFI/GPT Bootable disk image.” ([noble/current](https://cloud-images.ubuntu.com/noble/current/))
- Azure VHD, same release directory: `ubuntu-24.04-server-cloudimg-amd64-azure.vhd.tar.gz` (daily name: `noble-server-cloudimg-amd64-azure.vhd.tar.gz`). ([Azure upload doc](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/create-upload-ubuntu), [releases listing](https://cloud-images.ubuntu.com/releases/24.04/release/))

Checksums are `SHA256SUMS` and `SHA256SUMS.gpg` in that directory. On an Ubuntu machine the cloud-image keyring is `/usr/share/keyrings/ubuntu-cloudimage-keyring.gpg`. ([artifacts](https://documentation.ubuntu.com/public-images/public-images-reference/artifacts/))

**Convert with `qemu-img`, not `Convert-VHD`.** `qemu-img convert` takes `-f` and `-O` format names ([qemu-img](https://www.qemu.org/docs/master/tools/qemu-img.html)). QEMU’s VHDX format name is `vhdx`; legacy VHD is `vpc`. Practical command: `qemu-img convert -f qcow2 -O vhdx -o subformat=dynamic in.img out.vhdx`. `Convert-VHD` only converts between `.vhd` and `.vhdx`, chosen by the destination extension, and the disk must be offline ([Convert-VHD](https://learn.microsoft.com/en-us/powershell/module/hyper-v/convert-vhd?view=windowsserver2025-ps)). It does not read QCOW2. Grow the disk before first boot with `Resize-VHD`; cloud-init’s growpart module expands the root filesystem when the disk is larger than the image ([growpart](https://docs.cloud-init.io/en/latest/reference/modules.html#growpart)). A community script clears the NTFS sparse flag with `fsutil sparse setflag` after `qemu-img`; that requirement is **UNVERIFIED**.

**Secure Boot template:** `Set-VMFirmware -VMName <name> -EnableSecureBoot On -SecureBootTemplate MicrosoftUEFICertificateAuthority`. That template is the Microsoft UEFI CA used to sign third-party bootloaders. The same guidance says this template removes the Windows bootloader certificate, so a Windows guest needs `MicrosoftWindows` instead. ([Ben Armstrong, archived on Learn](https://learn.microsoft.com/en-us/archive/blogs/virtual_pc_guy/enabling-secure-boot-on-linux-with-the-windows-technical-preview), [archived Secure Boot write-up](https://learn.microsoft.com/en-us/archive/blogs/dubaisec/secure-boot-on-virtual-machines), [Set-VMFirmware](https://learn.microsoft.com/en-us/powershell/module/hyper-v/set-vmfirmware?view=windowsserver2025-ps)) Whether a fully patched Server 2022 host still boots current 24.04 shim with that template, given the 2023 UEFI CA servicing, is **UNVERIFIED**.

**NoCloud seeding.** cloud-init looks for a vfat or iso9660 volume whose label is `CIDATA`, with `user-data` and `meta-data` in the root. `meta-data` must contain `instance-id`. `vendor-data` and `network-config` are optional. The documented example is `genisoimage -output seed.iso -volid cidata -joliet -rock user-data meta-data` (the spec text says `CIDATA`; the example’s volume id is lowercase). Changing `instance-id` is what makes a later boot count as first boot. The cloud image has no default password; the example logs in as `ubuntu` only after user-data sets one. ([NoCloud](https://docs.cloud-init.io/en/latest/reference/datasources/nocloud.html)) On Windows, the ADK tool is `oscdimg -lCIDATA` ([oscdimg](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/oscdimg-command-line-options)). Attach with `Add-VMDvdDrive`.

The generic image searches NoCloud without an edit: the NoCloud doc’s own example boots “a disk Ubuntu cloud image” plus that seed and never tells you to change `datasource_list`. The Azure image does not. Microsoft’s prepare-for-Azure steps write `/etc/cloud/cloud.cfg.d/90_dpkg.cfg` containing `datasource_list: [ Azure ]`, and an Azure Local article shows that file already present on an Ubuntu Azure image and tells you to run `dpkg-reconfigure cloud-init` to switch it to NoCloud. ([create-upload-ubuntu](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/create-upload-ubuntu), [Azure Local Ubuntu image](https://learn.microsoft.com/en-us/azure/azure-local/manage/virtual-machine-azure-marketplace-ubuntu)) Azure’s own datasource reads an attached UDF CD (`ovf-env.xml`) and IMDS at `169.254.169.254`, not a cidata volume. ([Azure datasource](https://docs.cloud-init.io/en/latest/reference/datasources/azure.html))

**Hyper-V kernel pieces.** `hv_kvp_daemon` is not inside the kernel package. On 24.04 it is `/usr/sbin/hv_kvp_daemon` from `linux-cloud-tools-common`, with unit `hv-kvp-daemon.service` (`ExecStart=/usr/sbin/hv_kvp_daemon -n`, `ConditionVirtualization=microsoft`, bound to the vmbus `hv_kvp` device). The matching kernel-version package is `linux-cloud-tools-<version>-generic` or, on the Azure kernel, `linux-cloud-tools-azure` / `linux-cloud-tools-<version>-azure`. ([file list](https://packages.ubuntu.com/noble/all/linux-cloud-tools-common/filelist), [contents search](https://packages.ubuntu.com/search?keywords=hv_kvp_daemon&searchon=contents&suite=noble&mode=filename), [unit file](https://git.launchpad.net/~ubuntu-kernel/ubuntu/+source/linux/+git/noble/tree/debian/linux-cloud-tools-common.hv-kvp-daemon.service)) The noble man page says the daemon lets the host push configuration (including IP addresses) into the guest and read guest version info. ([man page](https://manpages.ubuntu.com/manpages/noble/man8/hv_kvp_daemon.8.html)) Microsoft’s own troubleshooting says the host learns the guest IP from this daemon, and that `Get-VM` will not show it if `hv-kvp-daemon` is not running; the synthetic NIC is required. ([Learn Q&A](https://learn.microsoft.com/en-us/answers/questions/5825554/linux-discovery-failing-with-azure-migrate)) The Hinara 24.04 script installs `linux-tools-virtual` and `linux-cloud-tools-virtual`. ([install.sh](https://github.com/Hinara/linux-vm-tools/blob/master/ubuntu/24.04/install.sh)) `linux-azure` is a separate Azure-tuned kernel; the generic cloud image does not need it for the in-tree Hyper-V drivers. Whether the generic 24.04 manifest already contains `linux-cloud-tools-*` is **UNVERIFIED** (check the `.manifest` next to the image). Key-Value Pair Exchange must be enabled on the VM; AVMA’s doc says that integration service is on by default for new VMs. ([AVMA](https://learn.microsoft.com/en-us/windows-server/get-started/automatic-vm-activation))

**First boot versus subiquity autoinstall.** A cloud image is an already-installed disk; first boot is cloud-init only. An ISO autoinstall runs the full installer. No vendor page gives a minute comparison. Any number is **UNVERIFIED**. Expect the cloud image to be ready when cloud-init finishes, and the ISO path to take as long as a full install.

## 2. RDP into Linux guests

**xrdp + XFCE, which is what Microsoft documents for Ubuntu 24.04.** Packages: `xfce4`, `xfce4-session`, `xrdp`. Then `systemctl enable xrdp`, `sudo adduser xrdp ssl-cert`, and `echo xfce4-session > ~/.xsession`. Do not pass `--no-install-recommends` to `xrdp` if you want `xorgxrdp`; without it, xrdp falls back to Xvnc. ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/use-remote-desktop)) `/etc/xrdp/startwm.sh` on Debian/Ubuntu ends in `wm_start`, which sources `/etc/X11/Xsession`, and Xsession runs `~/.xsession` when that file exists. ([upstream startwm.sh](https://fossies.org/linux/xrdp/sesman/startwm.sh)) Replacing the end of `startwm.sh` with `exec startxfce4` forces XFCE for every user; that is a local edit, not the Microsoft recipe. xrdp plus `xorgxrdp` starts its own X server, so it does not need the Hyper-V framebuffer or a GPU.

**polkit / colord.** Those prompts show up when `colord` (and an authentication agent) are installed. Ubuntu 24.04 no longer honors the old `.pkla` files; polkit rules are JavaScript under `/etc/polkit-1/rules.d/`. ([Ask Ubuntu on 24.04 polkit](https://askubuntu.com/questions/1524884/how-to-make-polkit-work-with-xrdp)) Microsoft’s xrdp article never mentions this. A minimal XFCE without `colord` often never shows the prompt. The exact rule text to allow `org.freedesktop.color-manager.create-device` is **UNVERIFIED** as an upstream Ubuntu file; it is a lab fix to test.

**Sound is optional and not in the Microsoft recipe.** The upstream module is [pipewire-module-xrdp](https://github.com/neutrinolabs/pipewire-module-xrdp). Whether noble has a binary package for it is **UNVERIFIED**.

**gnome-remote-desktop.** The daemon streams pixels through PipeWire and Mutter, not through its own X server. ([README](https://github.com/GNOME/gnome-remote-desktop/blob/master/README.md)) Three modes:

- Existing session (needs someone already logged into GNOME): `grdctl rdp set-tls-key`, `set-tls-cert`, `set-credentials`, `rdp enable`, `rdp disable-view-only`, then `systemctl --user enable --now gnome-remote-desktop.service`.
- Headless remote login (GDM): same commands with `grdctl --system`, certificates owned by the `gnome-remote-desktop` user, then `systemctl enable --now gdm.service` and `gnome-remote-desktop.service`.
- Headless single user: `grdctl --headless` and `systemctl --user enable --now gnome-remote-desktop-headless.service`.

TLS material comes from `winpr-makecert` (FreeRDP). No GNOME or Ubuntu document says this works on a Hyper-V VM whose only display is the Microsoft Hyper-V Video adapter. It can fall back to software rendering, but that is heavier than xorgxrdp, and Hyper-V enhanced session does not speak this protocol.

**Which is the better fit with no GPU:** xrdp + XFCE. It is the path Microsoft documents, it does not need GNOME or a GPU, and it is the server enhanced session already uses. gnome-remote-desktop is the right tool only if you specifically want a GNOME session and you accept an untested Hyper-V display path.

**Enhanced session (xrdp over vsock).** The host side is `Set-VM -VMName <name> -EnhancedSessionTransportType HvSocket`, documented in older Microsoft forum replies, not in a current Ubuntu 24.04 Learn article. ([archived reply](https://learn.microsoft.com/en-us/archive/msdn-technet-forums/d385a346-64ae-494c-8457-842b991e59c6)) The guest side is the linux-vm-tools script. Microsoft’s repo has no 24.04 script; the Hinara fork added `ubuntu/24.04/install.sh` on 2024-05-17. ([repo](https://github.com/Hinara/linux-vm-tools), [commit](https://github.com/Hinara/linux-vm-tools/commit/f2c76faf09849387ca7a6b1f99d5f623551af4e4)) That script installs `xrdp`, `linux-tools-virtual`, and `linux-cloud-tools-virtual`, then rewrites `/etc/xrdp/xrdp.ini`: `port=vsock://-1:3389` (this replaces TCP 3389), `security_layer=rdp`, `crypt_level=none`, `bitmap_compression=false`. It writes `/etc/xrdp/startubuntu.sh` (`GNOME_SHELL_SESSION_MODE=ubuntu`, `XDG_CURRENT_DESKTOP=ubuntu:GNOME`) and points `sesman.ini` at it, sets `FuseMountName=shared-drives`, and sets `allowed_users=anybody` in `/etc/X11/Xwrapper.config`. That is a GNOME session, not XFCE. Whether this still works on 24.04 is **UNVERIFIED**: the script exists, and no Microsoft test report says it passes. VMConnect’s enhanced-session client is not full `mstsc`; multi-monitor is one thing it does not offer. ([Learn Q&A](https://learn.microsoft.com/en-us/answers/questions/5995721/hyper-v-dual-monitor-on-windows-server-2022))

## 3. Windows 11 Enterprise 90-day evaluation as a Gen2 VM

**Requirements.** Generation 2 only. 4 GB RAM or more, 64 GB disk or more, two or more vCPUs, UEFI Secure Boot, TPM 2.0. On Hyper-V that is Secure Boot plus a virtual TPM. The vTPM does not depend on a TPM in the host. The host CPU must meet the Windows 11 CPU list, with a note that this host rule does not always apply. ([Windows 11 requirements](https://learn.microsoft.com/en-us/windows/whats-new/windows-11-requirements)) Secure Boot template for a Windows guest is `MicrosoftWindows`, the default, not `MicrosoftUEFICertificateAuthority`. ([archived template article](https://learn.microsoft.com/en-us/archive/blogs/dubaisec/secure-boot-on-virtual-machines)) vTPM: `Set-VMKeyProtector -VMName <name> -NewLocalKeyProtector` then `Enable-VMTPM -VMName <name>`. ([Enable-VMTPM](https://learn.microsoft.com/en-us/powershell/module/hyper-v/enable-vmtpm?view=windowsserver2022-ps), [key protector troubleshooting](https://learn.microsoft.com/en-us/troubleshoot/windows-server/virtualization/virtual-shielded-host-guardian-service))

**ISO.** Register and download from the Evaluation Center. There is no stable anonymous direct URL. The page currently offers Windows 11 Enterprise, version 26H2 (x64 and Arm64) and Enterprise LTSC 2024 (x64). It says: register, then install for a **90-day** evaluation; a product key is not required. ([Evaluation Center](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise))

**OOBE and a local admin.** The same page says: “To use Windows 11 Enterprise, you must sign into your PC with a Microsoft account. The option to create a local account will be made available at the time of the final release.” That sentence conflicts with the unattend reference below. Treat it as unsettled on this 26H2 ISO.

The unattend component is `Microsoft-Windows-Shell-Setup` (`processorArchitecture="amd64"`, `publicKeyToken="31bf3856ad364e35"`, `language="neutral"`, `versionScope="nonSxS"`), pass `oobeSystem`. Documented OOBE children: `HideEULAPage`, `HideOEMRegistrationScreen`, `HideOnlineAccountScreens`, `HideWirelessSetupInOOBE`, `HideLocalAccountScreen`, and `ProtectYourPC`. A local account is `UserAccounts/LocalAccounts/LocalAccount` with `Name`, `Group` = `Administrators`, and `Password/Value` plus `Password/PlainText`. Region settings are `Microsoft-Windows-International-Core` in the same pass (`InputLocale`, `SystemLocale`, `UILanguage`, `UserLocale`). Any screen you do not set still appears. ([Automate OOBE](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/automate-oobe), [HideOnlineAccountScreens](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-oobe-hideonlineaccountscreens))

`HideOnlineAccountScreens` was last updated on that page in 2020. Its text says it hides the sign-in page and that the sign-in page appears only if there is an internet connection. It does **not** say it removes the “connect to a network” requirement. `BypassNRO` is not an unattend setting. It is the script `%SystemRoot%\System32\oobe\BypassNRO.cmd`, which sets `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\OOBE` value `BypassNRO` (DWORD 1) and reboots. Whether that script, or the same registry value written from `Microsoft-Windows-Deployment` / `RunSynchronousCommand` in the `specialize` pass, still works on the 26H2 eval ISO is **UNVERIFIED**. Third-party write-ups say Microsoft removed the script from some 2025 Insider builds; that is not a Learn statement about this ISO.

**AutoLogon** is `Microsoft-Windows-Shell-Setup/AutoLogon`, valid in `auditSystem`, `oobeSystem`, and `specialize`. Children: `Username`, `Password` (`Value`, `PlainText`), `Enabled`, `Domain`, `LogonCount`. `LogonCount` is required. Setup deletes the AutoLogon credentials from the answer file after setup; the password remains in the Winlogon registry until the count is exhausted. Known bug: if `LogonCount` is greater than 0, Windows adds one, so the value cannot request exactly one logon. Workaround, documented on the same page: set `LogonCount` to 1 and add a `FirstLogonCommands/SynchronousCommand` that runs `reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" /v AutoLogonCount /t REG_DWORD /d 0 /f`. `LogonCount` of 0 means no autologon. ([AutoLogon](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-autologon), [LogonCount](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-autologon-logoncount))

**1920×1080 basic session.** `Set-VMVideo -VMName <name> -HorizontalResolution 1920 -VerticalResolution 1080`. The cmdlet’s own example is 1920×1200. The VM must be off. This is the synthetic display. ([Set-VMVideo](https://learn.microsoft.com/en-us/powershell/module/hyper-v/set-vmvideo?view=windowsserver2025-ps)) Enhanced session uses the VMConnect resolution dialog instead; that override is **UNVERIFIED** as an explicit sentence in the cmdlet doc.

**Pause Windows Update for five weeks.** Policy CSP Update: `PauseFeatureUpdates` stays in effect for **35 days** from `PauseFeatureUpdatesStartTime`, and quality updates are still offered while feature updates are paused. The matching policies are `PauseQualityUpdates` and `PauseQualityUpdatesStartTime`. Group Policy path: Computer Configuration → Windows Components → Windows Update → Manage updates offered from Windows Update. Registry key: `SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate` (ADMX `WindowsUpdate.admx`). `SetMaxPauseDays` allows 1–35, default 35. ([Policy CSP – Update](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-update)) A pause is not a permanent off switch; it expires. `SetDisableUXWUAccess` is the stronger “turn off the Windows Update UI” policy on the same page.

**First-run prompts that are documented:**

- Edge: policy `HideFirstRunExperience` (DWORD 1) at `SOFTWARE\Policies\Microsoft\Edge`. ADMX `MSEdge.admx`, path Administrative Templates/Microsoft Edge. This hides the first-run experience and splash screen. It does not disable sync prompts; that is `SyncDisabled`. ([Edge policy](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/hidefirstrunexperience))
- Privacy express settings: `ProtectYourPC` in the OOBE block. The value that turns express settings off is `3`. ([setting page](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/unattend/microsoft-windows-shell-setup-oobe-protectyourpc), [Automate OOBE](https://learn.microsoft.com/en-us/windows-hardware/customize/desktop/automate-oobe))
- OneDrive: policy `DisableFileSyncNGSC` = 1 under `SOFTWARE\Policies\Microsoft\Windows\OneDrive`. ([OneDrive group policy](https://learn.microsoft.com/en-us/sharepoint/use-group-policy))
- Teams autostart and the current new-Teams provisioned app: **UNVERIFIED**. There is no unattend element for it. Test against the ISO you actually download; the client packaging has changed more than once.

**Applying `install.wim` with no Setup UI.** The Windows 11 imaging doc uses the same commands as Server. Sample: partition with the UEFI diskpart script, then `dism /Apply-Image /ImageFile:%1 /Index:1 /ApplyDir:W:\`, then `bcdboot W:\Windows /s S:`. The same page says you may pass `bcdboot /bootex` so the boot files are signed for the Windows UEFI 2023 CA. ([Capture and apply a WIM](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/capture-and-apply-windows-using-a-single-wim?view=windows-11), [UEFI partition layout](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/configure-uefigpt-based-hard-drive-partitions?view=windows-11)) Gen2 needs an EFI system partition, an MSR, and a Windows partition. Pick the index with `dism /Get-ImageInfo`; the sample assumes index 1. Whether this eval ISO ships `sources\install.wim` or `install.esd` is **UNVERIFIED**. Setup’s hardware block (the appraiser) does not run during `Apply-Image`. The OS requirements (vTPM, Secure Boot, RAM, disk, CPU) still apply at boot. Copy the answer file to `W:\Windows\Panther\unattend.xml` before first boot; `oobeSystem` is not applied by the offline DISM pass. ([answer-file overview](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/windows-setup-automation-overview)) Offline servicing only: `DISM /Image:W:\ /Apply-Unattend:...`.

After the 90 days, or if you never activate, the Evaluation Center says the background goes black, a “not genuine” notice stays on screen, and the PC shuts down every hour. ([Evaluation Center](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-11-enterprise))

## 4. Windows Server 2025 activation for short-lived lab VMs

**MAK.** A MAK has a fixed activation limit tracked by Microsoft, not by the VM. Error `0xC004C020` means the limit is exceeded; the documented fix is to ask the licensing activation center for more activations, not to delete VMs. ([error codes](https://learn.microsoft.com/en-us/troubleshoot/windows-server/licensing-and-activation/troubleshoot-activation-error-codes)) Remaining count is visible in VAMT or the volume-licensing portal, not via `slmgr /dlv`. ([Learn Q&A](https://learn.microsoft.com/en-ca/answers/questions/5704294/could-you-please-tell-me-how-to-verify-the-total-n)) A hardware change or a reinstall consumes another activation; formatting the old disk does not return it. ([Learn Q&A](https://learn.microsoft.com/en-us/answers/questions/5911924/windows-server-mak-key-shows-already-used-(0xc004c)) No Learn article found says `slmgr /upk` or destroying a VM credits an activation back. Treat credit-back as unavailable.

**AVMA.** Requires an **activated Windows Server Datacenter** host with the Hyper-V role. It does not work on Standard, and it does not work on any hypervisor except Hyper-V. A host only activates guests of its own version and older. A **Server 2022 host cannot activate a Server 2025 guest.** A 2025 Datacenter host can activate 2025, 2022, 2019, 2016, and 2012 R2 guests, any of Datacenter, Standard, or Essentials. Data Exchange (KVP) must be enabled. Command: `slmgr /ipk <AVMA_key>`. The key can also go in an unattend file. ([AVMA](https://learn.microsoft.com/en-us/windows-server/get-started/automatic-vm-activation?tabs=server2025), [training module](https://learn.microsoft.com/en-us/training/modules/select-windows-server-editions-servicing-options-activation/5-implement-automatic-virtual-machine-activation))

Windows Server 2025 AVMA client keys from that page (tab `server2025`):

| Edition | Key |
| --- | --- |
| Datacenter | `YQB4H-NKHHJ-Q6K4R-4VMY6-VCH67` |
| Datacenter: Azure Edition | `6NMQ9-T38WF-6MFGM-QYGYM-88J4F` |
| Standard | `WWVGQ-PNHV9-B89P4-8GGM9-9HPQ4` |

These are public client keys, not MAKs. Failures are Event ID 12310 on the host and 12309 in the guest (`AVMA Success`, `Invalid Host`, `Invalid Data`, `Activation Denied`). KVP data is not secured; remove it if you replace the AVMA key.

**KMS / GVLK.** A GVLK only marks the machine as a KMS client. It does not activate anything until a KMS host answers. Install with `slmgr /ipk <GVLK>`. Server 2025 GVLKs: Standard `TVRH6-WHNXV-R9WG3-9XRFY-MY832`, Datacenter `D764K-2NDRG-47T6Q-P8T8W-YP6DF`, Datacenter: Azure Edition `XGN3F-F394H-FD2MY-PP6FD-8MCRC`. ([KMS client keys](https://learn.microsoft.com/en-us/windows-server/get-started/kms-client-activation-keys)) A KMS activation lasts 180 days and the client renews every 7 days by default. A Server 2022 KMS host can activate Server 2025 clients only after the February 13, 2024 update KB5034765 or a later cumulative update. ([KMS planning](https://learn.microsoft.com/en-us/windows-server/get-started/kms-activation-planning)) What stops working on a never-activated Server 2025 volume install is **UNVERIFIED**. Microsoft does not publish an hourly-shutdown rule for that case. The hourly shutdown below is for evaluation media. Check `slmgr /dlv` and `slmgr /xpr` rather than assuming the VM keeps working.

**Evaluation media.** Download from the [Windows Server 2025 Evaluation Center](https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2025). A Microsoft Q&A answer (2026-07-29) says the current period is 180 days and that Server 2025 allows one `slmgr /rearm`, adding another 180 days; confirm the remaining count with `slmgr /dlv` on the build you install. That rearm count is a Q&A claim, not a product-spec page, so the exact number is **UNVERIFIED** until `/dlv` shows it. `slmgr /rearm` itself is documented and is also what `sysprep /generalize` does. ([slmgr options](https://learn.microsoft.com/en-us/windows-server/get-started/activation-slmgr-vbs-options)) Older Microsoft material says an expired Server evaluation shuts down every hour; the current Windows 11 eval page says that explicitly, and the Server 2025 product page does not. Confirm on the guest.

**Eval to licensed:** `DISM /online /Get-TargetEditions`, then `DISM /online /Set-Edition:<edition> /ProductKey:<key> /AcceptEula`. The server restarts twice. You cannot convert a domain controller. The same article says a Standard *Core* evaluation can convert to retail Datacenter Core but not to retail Standard Core; always trust `Get-TargetEditions` on that image. ([conversion](https://learn.microsoft.com/en-us/windows-server/get-started/upgrade-conversion-options))

**Policy.**

- Long-lived servers on these Server 2022 hosts: AVMA cannot activate 2025 guests unless the host is upgraded to **2025 Datacenter**. Next best is a KMS host (a patched Server 2022 box can be that host) and the GVLKs above. Use a MAK only for a few machines you will not rebuild. Every rebuild burns a count, and nothing in the docs gives it back.
- Throwaway lab VMs: do not put a MAK on them. Use evaluation media and rearm while `/dlv` still shows rearms, and delete the VM before it expires. If a KMS host already exists, GVLKs are better than eval media because they are not a finite per-VM pool. AVMA is the right answer only after the host itself is 2025 Datacenter.

## 5. Screen recording with no GPU

The guest paints its own desktop on the Microsoft Hyper-V Video device. Basic session is that device. Enhanced session is RDP and is a different capture path.

**gdigrab** is the compatible choice. It is a Win32 GDI capture. `ffmpeg -f gdigrab -framerate 30 -i desktop ...` grabs the whole desktop of the session the process is running in; `title=<window>` grabs one window. Options include `draw_mouse`, `offset_x`, `offset_y`, `video_size`. ([FFmpeg devices](https://ffmpeg.org/ffmpeg-devices.html#gdigrab)) It does not need DXGI or a GPU. A Windows service runs in session 0 and cannot see the logged-on desktop, so the recorder has to be a process in that interactive session (a logon scheduled task, not a service). ([interactive services](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services))

**ddagrab** uses the Desktop Duplication API and returns D3D11 frames. Software x264 cannot encode them until you add `hwdownload,format=bgra`. ([FFmpeg ddagrab](https://ayosec.github.io/ffmpeg-filters-docs/7.0/Sources/Video/ddagrab.html), [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html#ddagrab)) `IDXGIOutput1::DuplicateOutput` returns `DXGI_ERROR_UNSUPPORTED` when the output does not support the current desktop mode (8 bpp and non-DWM desktops are the documented examples). ([DuplicateOutput](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutput1-duplicateoutput)) Whether the Microsoft Hyper-V Video adapter supports duplication at all is **UNVERIFIED**. If it does not, ddagrab fails and gdigrab still works.

**Windows.Graphics.Capture** captures a window or a monitor from a process that can create a `GraphicsCaptureItem`. ([screen capture](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/screen-capture)) No Microsoft page says it works on the Hyper-V video adapter. **UNVERIFIED.** It also has to run in the interactive session.

**CPU at 1920×1080, 30 fps, libx264 `veryfast`.** No vendor number exists for this guest. **UNVERIFIED.** `veryfast` is an x264 speed preset (`-c:v libx264 -preset veryfast`). The Hyper-V basic adapter has no NVENC, Quick Sync, or AMF device, so the encode is entirely on the vCPU. Budget at least one full core and measure; do not plan on a published percentage.

**Does the desktop keep rendering with no VMConnect client?** The synthetic display is a virtual device that stays attached when VMConnect closes. That is not the same as disconnecting an RDP session, which can lock the session. No Microsoft sentence says DWM keeps presenting frames in that case. **UNVERIFIED**; this is the first thing to test. If enhanced session is enabled, you are on the RDP path and this assumption is wrong.

**Keep the session unlocked**, all documented:

- `powercfg /change monitor-timeout-ac 0` and `powercfg /change standby-timeout-ac 0`. ([powercfg](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options))
- Security policy “Interactive logon: Machine inactivity limit” set to 0 so the machine does not lock on idle. ([policy](https://learn.microsoft.com/en-us/windows/security/threat-protection/security-policy-settings/interactive-logon-machine-inactivity-limit))
- Group Policy “Do not display the lock screen” (`NoLockScreen` = 1 under `SOFTWARE\Policies\Microsoft\Windows\Personalization`).
- AutoLogon, so a reboot returns to the desktop (section 3). Screensaver disable is **UNVERIFIED** as a single policy name; test it, because a screensaver still locks even when the monitor timeout is 0.

## 6. Input injection from the logged-on session

`SendInput` inserts events into the input stream of the session that calls it. ([SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)) pyautogui and pynput on Windows both end up there. ([pyautogui](https://pyautogui.readthedocs.io/en/latest/), [pynput](https://pynput.readthedocs.io/en/latest/)) A service in session 0 cannot inject into the logged-on desktop; the injector has to run in that session, same as the recorder. ([interactive services](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services))

Two separate blocks:

- **UIPI.** A medium-integrity process cannot send input to a high-integrity (elevated) window. The injector must be elevated to drive elevated windows. ([UIPI](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview))
- **UAC secure desktop.** The consent dialog runs on the Winlogon desktop, not the user desktop. `SendInput` from the user session, elevated or not, does not reach it. ([How UAC works](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-user-account-control-works)) For an automated walkthrough, don’t trigger UAC: keep the tools at the integrity level of the windows they touch, or pre-approve the actions. Turning UAC off is a golden-image choice, not required by the API.

**Defender and PyInstaller.** A onefile build unpacks a payload under `%TEMP%\_MEI...` at startup ([PyInstaller usage](https://pyinstaller.org/en/stable/usage.html)). Unsigned copies of that pattern are commonly flagged. The specific detection name is **UNVERIFIED** and changes. Legitimate avoidance, not packing tricks: Authenticode-sign the exe, prefer a onedir build or an MSI over onefile, and in the golden image add a path exclusion with `Add-MpPreference -ExclusionPath`. ([Defender exclusions](https://learn.microsoft.com/en-us/defender-endpoint/configure-exclusions-microsoft-defender-antivirus)) Signing reduces SmartScreen and reputation hits; it is not a promise that Defender will ignore the file. False positives on your own binary can be submitted at the [Defender file submission portal](https://www.microsoft.com/en-us/wdsi/filesubmission).

**OpenCV templates.** `cv2.matchTemplate` compares a pixel patch against the frame. ([tutorial](https://docs.opencv.org/4.x/d4/dc6/tutorial_py_template_matching.html)) It only works if the screenshot and the template share the same resolution and DPI. Fix the mode with `Set-VMVideo` at 1920×1080 and force 100% scale (96 DPI). Windows will sometimes pick 150% on a virtual monitor even at 1920×1080; whether this guest does that is **UNVERIFIED**. Capture templates on the same VM after scale is locked. DPI changes, ClearType, and subpixel antialiasing all break a tight template match.

## Facts we can rely on

- The Hyper-V disk is the generic QCOW2 `ubuntu-24.04-server-cloudimg-amd64.img`, converted with `qemu-img -O vhdx`. The Azure `.vhd.tar.gz` is the wrong artifact, and its cloud-init datasource list is Azure-only.
- Linux Gen2 Secure Boot template name is `MicrosoftUEFICertificateAuthority`. Windows guests use `MicrosoftWindows`.
- NoCloud seed is a `CIDATA` ISO or FAT volume containing `user-data` and `meta-data` (`instance-id` required). The generic image searches it by default; the Azure image does not.
- Guest IP on the host comes from `hv-kvp-daemon` (`linux-cloud-tools-common` plus the matching `linux-cloud-tools-*` package), and KVP is on by default.
- Headless Linux desktop without a GPU: `xrdp` + `xfce4` + `~/.xsession` containing `xfce4-session`. gnome-remote-desktop is a GNOME/PipeWire stack and is not the enhanced-session transport.
- Enhanced session is xrdp on `vsock://-1:3389` plus `Set-VM -EnhancedSessionTransportType HvSocket`. A 24.04 script exists in the Hinara fork; Microsoft does not certify it.
- Windows 11 eval is the Evaluation Center 26H2 ISO, 90 days, Gen2, 4 GB, 64 GB, 2 vCPUs, Secure Boot, vTPM. Expiry or failure to activate shuts the PC down hourly.
- `DISM /Apply-Image` plus `bcdboot` is the supported no-Setup apply path for Windows 11, same tools as Server.
- A Server 2022 host cannot AVMA-activate a Server 2025 guest. AVMA needs Datacenter, and the host version must be at least the guest version. MAK counts are not documented to come back when a VM is destroyed.
- Screen capture with no GPU is `gdigrab` inside the logged-on session. `ddagrab` needs Desktop Duplication, which this adapter may not provide.
- `SendInput` (pyautogui / pynput) must run in the logged-on session, elevated if the target window is elevated, and cannot reach the UAC secure desktop.
